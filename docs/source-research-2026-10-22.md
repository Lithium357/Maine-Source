# Data source expansion research

Researched 2026-10-22. These are recommendations, not implemented connectors. Sizes describe particular releases, not download promises. Access conditions and manifests must be checked again when implementing a connector.

Implementation update: version 0.1.3 implements a subset of these ideas, with narrower scopes where stated (for example, arXiv abstracts and CKAN catalog metadata). See the [current coverage table](../README.md#source-coverage); this research document is not the authoritative implementation status.

## Recommendation

Build bulk ingestion before adding a long list of record-at-a-time APIs. The highest-return first additions are Common Pile and FineWeb presets through an upgraded Hugging Face reader, Wikimedia exports, OSV, and reusable CKAN/Socrata/Dataverse connectors. Add Software Heritage, scientific papers, patents, and structured scientific collections next.

Keep three concepts separate in the UI: a **provider** (Hugging Face), a **dataset preset** (Common Pile), and a **collection recipe** (English documents, selected licenses, 5 GB accepted output). Several presets can share one connector. Existing Hugging Face, Wikipedia, GitHub, and Europe PMC support does not imply that their bulk datasets already work.

Support text, code, tables, graphs, and original files as distinct content types. Search indexes, offline archives, literature discovery, vulnerability matching, dashboards, and statistical analysis are useful outcomes alongside training datasets.

## Cybersecurity and engineering packs

In addition to NVD, CISA, GitHub, and OSV, offer these selectable sources. Some are small curated knowledge bases rather than large training corpora; their value is precision and structure.

- **MITRE ATT&CK:** techniques, tactics, relationships, mitigations, and references. Prefer published STIX bundles for snapshots; TAXII is available for structured access. Retain MITRE terms and stable object IDs. Useful for threat-intelligence search and mapping incident reports. [Official data formats](https://attack.mitre.org/resources/attack-data-and-tools/).
- **CWE and CAPEC:** software/hardware weaknesses and attack patterns. Import official XML/CSV and preserve relationships and notices. Good engineering reference and classification anchors. [CWE downloads](https://cwe.mitre.org/data/downloads.html), [CAPEC downloads](https://capec.mitre.org/data/downloads), [CAPEC terms](https://capec.mitre.org/about/termsofuse.html).
- **UNB Canadian Institute for Cybersecurity datasets:** network traffic and intrusion-detection datasets, including CSV flow records and PCAP. This needs structured/binary file support rather than the text collector. Capture each release's citation and usage requirements. Useful for traffic analysis and defensive detection research. [Official dataset catalog](https://www.unb.ca/cic/datasets/index.html).
- **Materials Project:** structured materials properties for engineering analysis and materials discovery. Uses its own account/API key; follow current API documentation rather than legacy endpoints. Preserve units, structures, calculation provenance, and applicable data terms. [Current API](https://docs.materialsproject.org/downloading-data/using-the-api/getting-started), [bulk guidance](https://docs.materialsproject.org/downloading-data/how-do-i-download-the-materials-project-database).

## Conditional / advanced additions

**Common Crawl** offers a petabyte-scale web archive and billions of pages per crawl. WET supplies extracted text, WAT metadata, and WARC original HTTP records. It is valuable for web research and archiving as well as model corpora, but requires streaming, decompression, URL-index selection, and substantial filtering. Public access to the archive does not grant blanket rights to original page content. Make this an advanced source after smaller bulk pipelines work. [Overview](https://www.commoncrawl.org/overview), [index](https://index.commoncrawl.org/).

**Semantic Scholar / S2ORC** offers scholarly datasets and structured paper text, but current API terms make the intended use important: the standard grant covers specified noncommercial research/education uses, with expanded uses requiring separate permission. This should be a conditional source with recorded access terms, not presented as universally unrestricted. Individual article licenses remain a separate question. [Dataset API](https://api.semanticscholar.org/api-docs/datasets), [API license](https://api.semanticscholar.org/license/), [S2ORC](https://github.com/allenai/s2orc/blob/master/README.md).

## Required product work

The current alpha collects small API responses and saves individual documents. It should not advertise terabyte-scale ingestion yet. Before enabling these sources:

1. **Stream and resume.** Read compressed JSONL, XML, archives, and Parquet incrementally. Save shard/record checkpoints and verify checksums or object versions. Pin repository revisions and dataset releases.
2. **Budget the whole operation.** Track downloaded bytes, temporary disk use, retained output bytes, elapsed time, and accepted records independently. A rejected document still consumed transfer and processing. Show estimates before downloading large shards.
3. **Support useful subsets.** Let users choose language, dates, categories, fields, corpus components, geographic regions, or table partitions. Offer reproducible sampling before a full collection. Do not silently collect only the first rows and call that representative.
4. **Detect incomplete access.** Hugging Face's converted Parquet output can be partial; inspect completeness fields and original manifests. Do not report a complete dataset merely because a viewer endpoint has no more rows. [Parquet API behavior](https://huggingface.co/docs/dataset-viewer/en/parquet).
5. **Preserve originals and structure.** Retain an optional original record/file beside derived text. Tables need column types and units; graphs need IDs and edges; translation data needs aligned pairs. Export formats should eventually include CSV and Parquet alongside JSONL/text.
6. **Separate rights layers.** Record the provider's access terms, dataset/database license, individual content license, and evidence scope. Metadata licenses do not automatically apply to documents. The 1–10 evidence slider must not turn a known incompatible license or provider restriction into permission.
7. **Deduplicate across sources.** Use DOI/PMCID, CVE/GHSA aliases, repository revisions, file hashes, and text fingerprints where applicable. Track lineage instead of counting mirrors as independent examples.
8. **Protect evaluation boundaries.** Preserve split labels and benchmark IDs so training recipes can exclude evaluation material. Offer collection purposes such as Training, Retrieval/Search, Archive, and Analysis without changing underlying rights rules.

## Suggested implementation order

1. Bulk reader foundations, preview/sample mode, transfer/disk budgets, and manifests.
2. Common Pile/FineWeb presets, Wikimedia exports, and OSV/advisory snapshots.
3. CKAN, Socrata, and research Dataverse to broaden the audience with reusable connectors.
4. Software Heritage, OpenAlex, PMC/arXiv, and USPTO for code/science/engineering depth.
5. Tables, graphs, geographic data, and binary archives; then NOAA, OpenStreetMap, Materials Project, and CIC datasets.
6. Common Crawl and other very large archives after checkpointing, filtering, and storage behavior have been validated at smaller scale.

In the checkbox source selector, group these by subject and tag them with content type, credential requirement, bulk availability, and implementation status. Show the chosen release and expected download size in the collection setup, with advanced settings available after the simple selection screen.
